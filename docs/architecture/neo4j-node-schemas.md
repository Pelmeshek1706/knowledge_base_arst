This file defines the MVP Neo4j node labels and their required and optional properties.

## Content

### Responsibility

Node schemas define the graph representation of processed documents, chunks, tags, entities, and file-extension document types.

MVP node labels:

```text
(:Document)
(:Chunk)
(:Tag)
(:Entity)
(:DocumentType)
```

### `(:Document)`

Represents one processed document record.

For local MVP, a document is one local source file:

```text
PDF
DOCX
Markdown
TXT
XLSX workbook
```

For future sources, a document can represent:

```text
Confluence page
Jira issue
Gmail thread
Google Doc
Google Sheet
Google Slide
external URL
manual upload
```

#### Required properties

| Property | Type | Description |
|---|---:|---|
| `document_id` | `STRING` | Stable UUID generated by the application. Primary graph ID. |
| `source_id` | `STRING` | Source identifier. For local files, relative file path. |
| `source_type` | `STRING` | `local_file` in MVP. |
| `file_path` | `STRING` | Relative file path from project root. |
| `file_name` | `STRING` | File name with extension. |
| `file_extension` | `STRING` | `pdf`, `docx`, `md`, `txt`, `xlsx`. |
| `document_type` | `STRING` | One value based on extension: `pdf`, `docx`, `markdown`, `text`, `spreadsheet`. |
| `title` | `STRING` | Human-readable title, usually file stem. |
| `normalized_title` | `STRING` | Normalized title for matching. |
| `summary` | `STRING` | Document-level summary. |
| `raw_bytes_hash` | `STRING` | SHA256 over raw bytes. |
| `extracted_text_hash` | `STRING` | SHA256 over normalized extracted text. |
| `content_hash` | `STRING` | Canonical hash used for compatibility. Defaults to `raw_bytes_hash`. |
| `created_at` | `STRING` or `DATETIME` | Source file creation time if available. |
| `modified_at` | `STRING` or `DATETIME` | Source file modified time. Used for canonical selection. |
| `ingested_at` | `STRING` or `DATETIME` | Time when processed by `personal_kb`. |
| `processing_status` | `STRING` | `processed`, `failed`, `skipped`, `duplicate`, `versioned`. |
| `is_duplicate` | `BOOLEAN` | True when exact duplicate is detected. |
| `canonical_document_id` | `STRING?` | Newest/canonical document ID for duplicate/version group. |

#### Optional properties

| Property | Type | Description |
|---|---:|---|
| `schema_version` | `STRING` | Processed JSON/schema version. |
| `parser` | `STRING` | Parser used: `pdfplumber`, `mammoth`, `openpyxl`, etc. |
| `chunker` | `STRING` | Chunking strategy used. |
| `llm_model` | `STRING` | LM Studio model used for extraction/summarization. |
| `embedding_model` | `STRING` | Embedding model used. |
| `embedding_dimension` | `INTEGER` | `1024` for `Qwen/Qwen3-Embedding-0.6B`. |
| `tag_names` | `LIST<STRING>` | Denormalized convenience list. Optional. |
| `entity_names` | `LIST<STRING>` | Denormalized convenience list. Optional. |
| `error_message` | `STRING?` | Failure reason when `processing_status = failed`. |
| `metadata_json` | `STRING?` | Serialized metadata for implementation convenience. |

#### Notes

- `summary` is a property, not a separate `Summary` node.
- `document_type` is intentionally simple and extension-based.
- Semantic categories such as `invoice`, `budget`, `article`, `report`, `meeting_notes` should be represented as `Tag` nodes.

### `(:Chunk)`

Represents a retrieval unit for RAG and source-grounded Q&A.

#### Required properties

| Property | Type | Description |
|---|---:|---|
| `chunk_id` | `STRING` | Stable UUID. Primary chunk ID. |
| `document_id` | `STRING` | Parent document ID. Duplicated for easier queries. |
| `chunk_index` | `INTEGER` | Position inside document. |
| `text` | `STRING` | Full chunk text. Required for Q&A. |
| `summary` | `STRING` | Chunk summary. |
| `file_path` | `STRING` | Relative source file path. |
| `embedding` | `LIST<FLOAT>` | 1024-dimensional local embedding. |
| `embedding_model` | `STRING` | `Qwen/Qwen3-Embedding-0.6B`. |
| `embedding_dimension` | `INTEGER` | `1024`. |

#### Source reference properties

| Property | Type | Used by |
|---|---:|---|
| `page` | `INTEGER?` | PDF |
| `section` | `STRING?` | DOCX, Markdown |
| `sheet` | `STRING?` | XLSX |
| `cell_range` | `STRING?` | XLSX |
| `source_ref_json` | `STRING?` | Optional serialized full source reference. |

#### Optional properties

| Property | Type | Description |
|---|---:|---|
| `char_count` | `INTEGER` | Chunk character count. |
| `token_count` | `INTEGER?` | Approximate token count if available. |
| `tag_names` | `LIST<STRING>` | Denormalized tag names. |
| `entity_names` | `LIST<STRING>` | Denormalized entity names. |
| `created_at` | `STRING` or `DATETIME` | When chunk node was created. |
| `updated_at` | `STRING` or `DATETIME` | When chunk node was updated. |

#### Notes

- Chunk text is intentionally stored in Neo4j for MVP convenience.
- If storage grows too large later, chunk text can be moved to JSON-only storage and Neo4j can keep summaries/source refs.

### `(:Tag)`

Represents normalized topics/keywords.

Examples:

```text
budget
accounting
invoice
wp2
architecture
jira
deployment
```

#### Required properties

| Property | Type | Description |
|---|---:|---|
| `tag_id` | `STRING` | Deterministic ID: `tag::<normalized_name>`. |
| `name` | `STRING` | Display name. |
| `normalized_name` | `STRING` | Unique normalized tag name. |

#### Optional properties

| Property | Type | Description |
|---|---:|---|
| `created_at` | `STRING` or `DATETIME` | Creation time. |
| `updated_at` | `STRING` or `DATETIME` | Last update time. |
| `source` | `STRING` | `llm_extraction`, `manual`, `rule_based`. |

#### Notes

- Confidence should usually live on the `HAS_TAG` relationship, because tag confidence is context-specific.
- Tag nodes are shared across documents and chunks.

### `(:Entity)`

Represents normalized extracted entities.

MVP entity types:

```text
Person
Organization
Project
Topic
DocumentType
Date
MoneyAmount
Account
Invoice
Task
Technology
UnknownEntity
LinkedEntity
```

#### Required properties

| Property | Type | Description |
|---|---:|---|
| `entity_id` | `STRING` | Deterministic ID or UUID. Recommended: `entity::<type>::<normalized_name>`. |
| `entity_key` | `STRING` | Unique key: `<type>::<normalized_name>`. |
| `name` | `STRING` | Display name. |
| `normalized_name` | `STRING` | Normalized name. |
| `type` | `STRING` | Entity type. |

#### Optional properties

| Property | Type | Description |
|---|---:|---|
| `summary` | `STRING?` | Aggregated summary of this entity across documents/chunks. |
| `created_at` | `STRING` or `DATETIME` | Creation time. |
| `updated_at` | `STRING` or `DATETIME` | Last update time. |
| `source` | `STRING` | `llm_extraction`, `rule_based`, `manual`. |

#### Notes

- Use a single `Entity` label with a `type` property in MVP.
- Do not create labels like `:Person`, `:Project`, `:Invoice` yet.
- Secondary labels may be useful later, but they complicate graph sync and schema migrations.

### `(:DocumentType)`

Represents simple extension-based document type.

#### Allowed values

| Extension | `DocumentType.name` |
|---|---|
| `.pdf` | `pdf` |
| `.docx` | `docx` |
| `.md` | `markdown` |
| `.txt` | `text` |
| `.xlsx` | `spreadsheet` |

#### Required properties

| Property | Type | Description |
|---|---:|---|
| `name` | `STRING` | Unique document type name. |
| `normalized_name` | `STRING` | Same as name in MVP. |

## Failure modes / risks

| Risk | Impact | Mitigation |
|---|---|---|
| Missing required node property | Failed or incomplete graph sync | Validate required fields in Pydantic before graph sync. |
| Inconsistent tag/entity normalization | Weak retrieval and duplicate nodes | Normalize with lowercase, trim, and repeated-space collapse. |
| Vector dimension mismatch on chunks | Vector search failure | Require `embedding_dimension = 1024` before sync. |
| Over-specific entity labels in MVP | Schema migration complexity | Use one `Entity` label with a `type` property. |
| Large chunk text in Neo4j | Larger database size | Accept for MVP; move text to JSON-only later if needed. |

## Validation

Validate node schemas by checking that:

- every `Document` has the required IDs, hashes, type, timestamps, status, duplicate fields, and summary fields;
- every `Chunk` has a parent `document_id`, `chunk_index`, text, source reference fields, embedding, model name, and `embedding_dimension = 1024`;
- tag uniqueness is based on `normalized_name`;
- entity uniqueness is based on `entity_key`;
- document type values are limited to `pdf`, `docx`, `markdown`, `text`, and `spreadsheet`;
- summaries remain node properties, not `Summary` nodes;
- semantic categories remain tags, not document type values.
